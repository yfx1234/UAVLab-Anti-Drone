# USB 500 万像素相机工作台部署记录

## 设备与版本

2026-10-21 按用户要求，通过 SSH 在其 Jetson 上启动 USB 相机实时页面。该设备的实际情况单独记录，不覆盖仓库现有 ZED / NX16 环境清单。

- Jetson 地址：`192.168.1.44`，SSH 用户 `uavlab`；登录凭据不保存到源码或配置。
- 系统报告：Orin NX Engineering Reference Developer Kit Super、Ubuntu 22.04.5、内核 5.15.148-tegra、Python 3.10.12、OpenCV 4.5.4。
- 相机：`LRCP 0G05B10`，序列号 `SN0001`，UVC 驱动 `uvcvideo`。
- 采集节点：`/dev/video0`；`/dev/video1` 是同一设备的另一节点，不能据此当作另一台相机。
- 使用稳定路径：`/dev/v4l/by-id/usb-LRCP_ZWAK_LRCP_0G05B10_SN0001-video-index0`。
- USB 拓扑显示相机连接速率为 `5000M`；MJPG 枚举包括 `2592×1944` 的 10/15/20/25/30/50/60 fps 等规格。枚举值不是已验证的持续性能。

## 部署与入口

部署前检查设备占用、端口和目标目录：相机无采集拥有者，8768 无监听，`~/usb-camera-preview` 尚不存在。将仓库 `usb-camera-preview/` 的程序和 HTML 上传到该独立目录，并在执行前逐文件核对 SHA256。原工作台的 8767 服务继续保留。

板端程序：`/home/uavlab/usb-camera-preview/usb_preview.py`。本次参数：

```bash
python3 -u /home/uavlab/usb-camera-preview/usb_preview.py \
  --device /dev/v4l/by-id/usb-LRCP_ZWAK_LRCP_0G05B10_SN0001-video-index0 \
  --width 2592 --height 1944 --fps 15 --fourcc MJPG \
  --host 0.0.0.0 --port 8768
```

当前后台实例的输出保存在 `~/usb-camera-preview/usb_preview.log`。需要重新启动前，先用 `pgrep -af 'usb_preview[.]py'` 确认是否已有该相机实例；程序也会对同一设备加锁。未安装开机自启。

电脑直接访问板端 8768 超时，但板端本机 HTTP 正常。因此本次通过 SSH 本地转发显示，未调整防火墙或网络配置：

```powershell
ssh -N -L 127.0.0.1:8768:127.0.0.1:8768 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 uavlab@192.168.1.44
```

保持该 SSH 连接，浏览器打开 `http://127.0.0.1:8768/`。这与原 ZED 工作台的 `http://127.0.0.1:8767/` 是两个入口。USB 页面提供实时监看、实际尺寸、预览帧率、截图与全屏；原 ZED 的深度、SVO、YOLO 与拦截链未接到这个 USB 入口。

## 实测与边界

- 板端 `/api/status` 显示 `online=true`、`width=2592`、`height=1944`、`error=null`。
- 电脑通过 SSH 转发下载 `/snapshot.jpg`，Pillow 实际解码尺寸为 `2592×1944`，即 5,038,848 像素；已目视确认有真实场景画面。
- 请求值为 15 fps，当前预览约 7.5 fps。该数是程序发布 JPEG 的速率；采集与解码、重编码都在同一个工作线程，不能将它等同为传感器最高帧率或浏览器端到端帧率。
- 连续取样 12 次、首尾间隔 12.438 秒，累计新增 93 个发布帧，实测 7.48 Hz；各次帧标识均更新，在线状态正常、帧未过期，首尾 JPEG 均通过 2592×1944 解码检查。
- 使用相机原尺寸，不把低分辨率图像放大为 500 万像素。JPEG 是有损预览，不宣称逐像素无损原片。
- 本次为短时显示与连续出帧检查，未进行长时间运行、最高帧率、录像、测距或目标识别精度验收。
