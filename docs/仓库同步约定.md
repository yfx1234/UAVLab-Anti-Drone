# GitHub 与 Gitee 同步约定

GitHub `main` 与 Gitee `master` 保存完整源码。每次发布将同一个提交推送到两边，提交 SHA、文件树和该提交可达的历史均保持一致。分支名称保留现状。

| 远端别名 | 仓库 URL | 完整源码分支 |
|---|---|---|
| `github` | `https://github.com/yfx1234/UAVLab-Anti-Drone.git` | `main` |
| `gitee` | `https://gitee.com/buaalab/anti-drone-interceptor.git` | `master` |

不同本地副本的 `origin` 指向可能不同；它不代表固定的平台。保留旧别名以兼容已有工具，日常发布明确使用上表两个别名。若别名缺失，按上表配置后先运行 `git remote -v` 确认 URL。

## 发布流程

先确认工作区状态，再获取两个远端的最新提交；已有未提交修改不得覆盖。两个默认分支发生分叉时，在本地合并并核查差异，保留已有历史，不强制推送。当前提交必须同时包含两个远端默认分支的历史。

在仓库根目录运行现有发布检查，并完成改动所需验证：

```text
python scripts/check_repository.py
```

提交后，将同一个 HEAD 推送到两个明确的分支：

```text
git push github HEAD:refs/heads/main
git push gitee HEAD:refs/heads/master
git ls-remote github refs/heads/main
git ls-remote gitee refs/heads/master
```

最后两条命令输出的 SHA 必须完全相同，并且等于本地 `git rev-parse HEAD`。若一边推送失败，明确报告未同步的平台与提交，排除原因后补推；另一边已成功不等于同步完成。远端出现新提交时重新获取和合并，不使用强制推送覆盖。

## 其他分支与部署

- Gitee `perception` 保留为仅感知源码副本；`netgun_intercept` 保留为历史分支，不能拿它们覆盖完整源码分支。
- 修复分支和其他开发分支按需保留，不要求两个平台拥有完全相同的全部分支、标签或平台设置。禁止使用 `git push --mirror` 整体覆盖远端。
- 仓库同步不等于板上部署。部署版本、工作区未提交修改和构建产物须另外核对，不因源码已同步就宣称运行版本或硬件验收完成。
