# 项目目录与维护入口

这是一个 ROS 2 多包仓库（`ros2_ws/src` 下 12 个可构建包），包含板端代码、
实验工具、模型资产与归档区。先按目录职责查找文件，再通过各包的构建、
安装和启动声明确认具体入口。

| 目录 / 文档 | 维护职责 |
|---|---|
| `ros2_ws/src/<包名>/` | 包级源码、接口、配置、启动声明与测试 |
| `ros2_ws/docs/` | 同步记录及交付资料 |
| `ros2_ws/scripts/` | 跨包实验脚本 |
| `deploy/` | 环境与服务部署 |
| `archive/` | 归档区：历史快照、零引用死文件、弃用整包（见其 README，不参与构建） |
| `board_misc/` | 从板端散落位置收集的历史参考文件（与仓库内权威文件重复的副本已去除） |
| `weights/` | 模型资产：每份内容只保留一个权威位置（见其 README 的等价表） |
| `tools/` | 通用仓库维护工具，不依赖 ROS，不加载节点或模型：`repository_audit.py`（文件结构/重复审计）、`code_redundancy_scan.py`（Python 定义级重复/零引用扫描） |
| **`docs/项目开发手册.md`** | **决策与约定的单一入口**：红线、火控律、物理依据、参数真源、环境配方、状态总账 |
| `docs/双目8m网枪拦截方案.md` | 网枪方案全文（v1→v4）+ 实施状态 + 仿真计划 |
| `docs/仓库结构审计.md` | 可重新生成的文件规模与完全重复内容清单 |
| `docs/结构整理变更记录.md` | 三轮整理/重构/WSL 验证的完整清单与回退方法 |
| `JETSON_V0_MIGRATION_PLAN.md` | 历史迁移台账与环境约束 |
| `VENDORED_DEPENDENCIES.md` | 仓库外依赖版本记录 |
| `1.md` | 现有操作文档 |

## 目录约定

- 包内 C++ 实现放在 `src/`，公开头文件放在 `include/<包名>/`。
- Python 模块放在对应包目录；`launch/`、`config/`、`test/` 分别存放启动声明、配置和测试。
- 独立工具按使用范围放在包内 `tools/` 或仓库根 `tools/`，避免复制到多个位置维护。
- 历史快照（`.bak_*`、`.prediction_before_*`、`.orig` 等）一律放 `archive/snapshots/`，
  不留在包源码树内；弃用整包放 `archive/deprecated_packages/`。
- 内容相同不意味着可以直接删除：配置路径、消息包名、安装清单和仓库外调用都可能依赖原位置；
  删除重复副本前先做全仓库引用核查和哈希配对校验（做法见 `docs/结构整理变更记录.md`）。

## 重新生成结构审计

在仓库根目录运行（Windows 使用 `py`，Linux 使用 `python3`）：

```text
py tools/repository_audit.py
```

工具仅向标准输出打印 Markdown，不改写项目文件。扫描 Git 已跟踪文件和未被忽略的新增文件，
用 SHA-256 核实非空文件的完全重复内容。顶层 `archive/` 归档区单独计数，
不计入活树的包、快照与重复指标；索引中已不存在的旧路径会单独列出
（整理后执行 `git add -A` 刷新索引即消失）。它不分析算法等价，不证明文件无人使用，
也不自动删除文件。审计报告是一次快照；文件变更后应重新生成。
