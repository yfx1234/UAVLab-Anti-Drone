# 网枪拦截链实机部署记录（2026-10-15）

首次把 netgun_intercept 拦截链部署到 Jetson Orin NX 实机（uavlab-desktop，
192.168.50.100，Ubuntu 22.04 / Humble / L4T 36.4.3），与 main 侧感知部署
（zed_perception_standalone + PC 8767 面板）共存，打通感知→拦截接口。
分支：`netgun_intercept`（基线 4866bda → 本次 78e7b02）。

## 部署内容

| 项 | 说明 |
|---|---|
| `src/zed_perception_bridge`（新包） | 感知桥：订阅 `/perception/observations_json`（PerceptionFrame 合同 v2 的 JSON 通道），映射发布 `/perception/depth/observation`（DepthObservation V1）。选 JSON 通道使拦截工作区构建期不依赖 `zed_perception_interfaces`。21 项纯逻辑单测（`python3 -m pytest src/zed_perception_bridge/test -q`，无 ROS 依赖） |
| `netgun_real.launch.py` | 增第四节点桥（`use_perception_bridge`/`bridge_selection` 参数）；**补制导输出重映射** `/px4_1/fmu/in/*→/fmu/in/*`（源码硬编码仿真命名空间，实机 PX4 收不到，板上话题列表实测发现）；内参更新为实测值 |
| `deploy/run_interceptor_stack.sh` | 板上 start/stop/status/log；nohup+setsid 防图传断连；环境链 humble→ros2_ws/install→install_perception→interceptor_ws |
| 板上 `~/interceptor_ws` | git 克隆（板无外网，经 git bundle 传输），`colcon build --packages-select netgun_intercept px4_offboard_tracking zed_perception_bridge -DBUILD_TESTS=OFF`（约 3 分钟；px4_msgs/anti_drone_interfaces 等由 ros2_ws/install 底座提供） |

映射与降级规则见 `src/zed_perception_bridge/README.md` 与
`src/zed_perception_bridge/zed_perception_bridge/mapping.py` 模块注释。要点：
`header.stamp` 透传原图曝光时刻；仅实测深度（`depth_measured_valid`）置
`depth_valid`，`size_estimate` 降级 bearing-only；generic 轨道默认排除。

## 板上环境（与感知节点一致性，实测踩坑）

- `ROS_DOMAIN_ID=0`；**`ROS_LOCALHOST_ONLY` 必须为 0**（感知节点进程环境即 0；
  设 1 会导致 DDS 互相不可见）。
- 板上 ros2 daemon 若以旧环境启动会污染 `ros2 topic list`；必要时
  `ros2 daemon stop && ros2 daemon start`（以正确环境）。
- PX4 QoS best_effort；桥/估计器观测链路 SensorDataQoS。

## 启动/停止（板端）

```bash
~/interceptor_ws/deploy/run_interceptor_stack.sh start    # 四节点：桥+估计+制导+火控
~/interceptor_ws/deploy/run_interceptor_stack.sh status
~/interceptor_ws/deploy/run_interceptor_stack.sh log
~/interceptor_ws/deploy/run_interceptor_stack.sh stop
```

感知（zed_perception_standalone）不在栈内，由 PC 8767 面板/supervisor 管理；
**拦截链要求 YOLO 开启**（supervisor `set_detector`；开启时同步计算深度）。

飞控未接时用 `tools/board_test/` 三件套完成全链闭环验证（真实
netgun_real.launch 四节点，仅感知源与飞控为受控模拟）：

- **mock_px4_node.py**：模拟飞控——发布 /fmu/out/{attitude,local_position,
  status}（板时戳、px4 QoS、**xy_valid/z_valid/heading_good_for_control 必须
  置位**，制导只接受带有效标志的位置消息），闭环消费 /fmu/in/trajectory_
  setpoint（位置/速度/加速度前馈），engage 开关门控（armed+offboard），
  倾转 θ=atan(a/g)、yaw 伺服运动学模型。
- **synthetic_perception_node.py**：虚拟相机——按 mock 位姿把固定世界目标
  （默认正上方 11.6m）投影为 PerceptionFrame v2 JSON（合同字段逐字对齐，
  深度门 0.35–10.0m），发布到 /test/perception/observations_json。
- **fullchain_test.py**：编排器（日志驱动）——判定 P0 节点启动→P1 估计器
  init→P2 engage 后制导 TAKEOFF/TRACK→P3 NETGUN FIRE；engage 用一次性
  CLI 发布；rc_gated 不变量校验（VehicleCommand 必须为 0）；bag+summary
  留证。**运行前必须停生产拦截栈**（同话题）；桥输入用 launch 参数
  `bridge_input_topic` 重定向，不碰真实感知。
