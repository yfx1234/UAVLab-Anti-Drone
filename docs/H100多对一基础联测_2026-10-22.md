# H100 多对一基础联测

## 结论与边界

用户完成新增模块配对后，地面电脑可以经 H100 同时访问 NX 与新增 Nano 测试板。已验证两节点并行 ICMP 及同时保持 SSH 会话；不代表双路视频、并发吞吐、远距离、长期稳定或重启自动恢复验收。

测试日期：2026-10-22（America/New_York）。原厂依据为用户提供的 `C:/Users/yfx33/Desktop/H100模块使用说明书1.3.pdf` 第 5—6 页：一个 AP、最多 31 个 STA，设备手动配置同网段地址，新增节点逐个配对。

## 地址与实际网口

| 设备 | 图传 IPv4 | Linux 网口 | 实测 MAC |
|---|---|---|---|
| 地面 Windows | 192.168.50.101/24 | 以太网 | 未在本报告核对 |
| NX | 192.168.50.100/24 | enx0826ae36fd65 | 08:26:ae:36:fd:65 |
| 新增板（用户称 Nano） | 192.168.50.102/24 | enP8p1s0 | 3c:6d:66:de:45:47 |

两板 hostname 都为 `uavlab-desktop`、用户都为 `uavlab`，因此使用地址与 MAC 区分。新增板的 `/proc/device-tree/model` 返回通用的 Orin NX 开发套件字符串，本报告不据此认定实际模组型号。

Nano 的 Wi-Fi DHCP 地址在测试时为 `192.168.1.44`，NX 为 `192.168.1.23`；Wi-Fi SSH 用于配置与排查，不计作图传通信证据。Windows Wi-Fi 为 `192.168.1.234`，与图传网段分开。

## 配置

Nano 通过原 Wi-Fi SSH 新增 NetworkManager 配置 `h100-nano`，绑定 `enP8p1s0`，手动地址 `192.168.50.102/24`，不设默认路由，IPv6 禁用，自动连接优先级 100。原有 `Wired connection 1` DHCP 配置保留，Wi-Fi 默认出口未变。

NX 配对和网络配置未改动；未操作相机、飞控或 QGC 服务。未保存任何密码。

## 观测结果

| 检查 | NX | Nano |
|---|---|---|
| 首轮各 12 个 ICMP 包 | 12/12，0% 丢包；平均 12 ms，9—21 ms | 12/12，0% 丢包；平均 9 ms，6—13 ms |
| 两目标同时启动，各 16 个 ICMP 包 | 16/16，0% 丢包；平均 11 ms，9—18 ms | 16/16，0% 丢包；平均 11 ms，5—32 ms |
| 并行 SSH，远端等待 4 秒后回读接口 | 成功，.100 接口仍 UP | 成功，.102 接口仍 UP |

Windows 邻居表同时存在两个地址及各自不同的 MAC。SSH 查询目标明确为 `.100` 和 `.102`；Nano 使用已知 Wi-Fi 主机密钥别名 `192.168.1.44` 核对主机身份。

Nano 首次图传 SSH 握手曾超时，随后重试及并行会话均成功，不能由短测断言完全没有瞬时连接问题。Nano 主动 ping Windows 未收到回复，但同期 TCP SSH 已建立；未进一步区分 Windows ICMP 策略与链路因素。
