# 飞控经 QGC 重启后的 USB 转发失联

## 结论

用户在 QGC 重启飞控时复现失联。飞控 USB 重新枚举后，MAVProxy 进程保持运行，却仍持有已删除设备的文件描述符；重新枚举的稳定 by-id 链接已指向新设备。重启 NX 用户服务 `qgc-mavlink-forward.service` 后恢复真实心跳与 QGC 显示。

这是已验证的运行期恢复，不是自动重连永久修复。未修改飞控参数、固件、MAVProxy 源码或服务配置；飞控重启由用户操作，助手未发送重启、解锁、运动或击发指令。

## 环境与来源

- 检查日期：2026-10-25，America/New_York；NX 时钟存在开机跳变，持续时间按电脑单调时钟计算。
- NX 图传地址 `192.168.50.100`，电脑 `192.168.50.101`，QGC 接收 UDP 14550；只读监测绑定已配置的分流口 UDP 14551，不争用 USB。
- 原始时间线：`C:/Users/yfx33/Documents/Codex/qgc-reboot-check/20261025-102248.jsonl`，保留在本机；不包含凭据。
- 用户服务完整启动参数仍保留 14550、14551 与本机 14555 输出；后者是现有本机服务使用的通信端点。

## 复现时间线

以下 elapsed_s 从电脑监测开始计。

| 时间 | 观测 |
|---|---|
| 0.38 s | by-id 指向 ttyACM1，inode 1158；MAVProxy PID 1458 正在使用相同设备 |
| 25.05 s | by-id 设备消失；PID 1458 仍持有 ttyACM1 (deleted)、inode 1158 |
| 27.50 s | 心跳超过 3 秒未到达 |
| 31.77 s | by-id 已指向 ttyACM0、inode 1180；旧进程仍持有 deleted 的 ttyACM1 |
| 50.12 s | 仍无新心跳，进程 active，服务 NRestarts=0 |
| 59.23 s | 助手重启转发服务后出现新进程 PID 11248 |
| 59.30 s | 飞控 system 2/component 1 的真实心跳恢复；与上一心跳间隔 34.99 秒 |
| 59.73 s | 新进程持有 ttyACM0，inode 1180 与 by-id 设备一致 |

服务日志对应记录：PREFLIGHT_REBOOT_SHUTDOWN 已接受、link 1 down、重复 no link。此前另一次重枚举曾在约 7 秒后自行重新打开设备，因此故障呈间歇性；不能认定所有重启都会失败。

## 恢复与验证

登录 NX 后执行：

```bash
systemctl --user restart qgc-mavlink-forward.service
```

该操作会短暂中断所有依赖此转发进程的通信端点，不只 QGC；此次心跳显示飞控未解锁，未操作现有本机击发服务。新服务的 USB 描述符、电脑分流口真实心跳及 QGC 实时姿态/状态显示均已核对。

QGC 恢复后仍显示 Not Ready；先前界面中的指南针不一致、无有效位置及无遥控输入属于飞行准备问题，不作为 USB 通信故障修复的验收依据。

## 后续未完成

- 为转发服务实现受控的设备消失/重新枚举监测与重开，不能仅依赖进程退出自动重启。
- 需保留现有全部 UDP 输出；不能以另开程序争读 USB 的方式做健康检查。
- 在未解锁且用户现场确认条件下，多次重复真实 USB 重枚举，验证 QGC 与各依赖端点恢复；永久修改需先在仓库实现并按维护规则部署。
