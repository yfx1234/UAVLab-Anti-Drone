## 四、数据链修复总账（2026-10-12 白天，est=0 问题全链路解决）



原问题 4（估计器→火控 est=0）拆出来其实是**六个叠加的集成 bug**，
按发现顺序全部修复并验证：

| # | 问题 | 现象 | 修复 |
|---|---|---|---|
| 1 | 估计器姿态容差未放宽 | 相机 0.2s、估计器仍 0.05s → 拒收 | launch 补 `attitude_sync_tolerance_s: 0.2` |
| 2 | setpoint 未置 NaN | position=0 被当"回原点"，压制爬升 | position/accel/jerk 置 NaN（旧节点同款） |
| 3 | 垂直速度符号反 | NED z 向下为正，+vz=下钻 | `vz_hold = gain*(alt - hold)` |
| 4 | 虚拟目标时钟未锚定 | 目标 x=1.79e9m（epoch 当 elapsed） | target_state_source 无 common_origin 时锚定节点启动时刻 |
| 5 | 目标不等追踪机就位 | 目标提前离场出视场 → 估计断流死锁 | guidance 进 TRACK 发 takeoff-ready（latched）+ launch 等待开关 |
| 6 | 裁判从未在 falcon_ws 构建 | 跑的是 UAV_ws 旧版（旧语义、无埋点） | `colcon build --packages-select virtual_interception_referee` |
| + | 火控授权对齐镜像 | 否则静止悬停段秒开火，矩阵无意义 | `attack_enable_delay_s: 10.0`（=目标运动延时） |

**排障方法论（可复用）**：诊断埋点 + 话题抓包。估计器加 obs/inv/attmiss/acc
计数器、strike 加 est 三分量分解（v/acc/age），一次运行定位一层；
`ros2 topic echo --field` 抓 target state 的 x=1.79e9 直接实锤时钟 bug。

**当前状态（2026-10-12 夜终版）**：多轮矩阵触发 95.6%/命中 100%/
miss 0.023m，全面超过镜像参考（91%/100%/0.14-0.61m）——仿真验证完成。
唯一非满分格 s_curve@4.0（1/3 触发，残余方差，未再追）。

| 坑 | 症状 | 解决 |
|---|---|---|
| 中文路径经 wsl.exe 传递损坏 | 变量为空 | 用 base64 管道：`echo $b64 \| base64 -d \| bash` |
| wsl.exe 传参剥双引号 | bash -c 内嵌脚本引号全丢、grep 报错 | 脚本写 Windows 临时文件，WSL 内 `tr -d "\r" < /mnt/c/... \| bash` 中转 |

| /mnt/g 9p 文件系统 mtime 漂移 | colcon 不重编已改文件 | `rm -rf build/<pkg> install/<pkg>` 后全量重编 |

| NED z 向下为正 | +vz 是下降不是爬升 | 爬升指令必须为负值 |

## 九、经验教训（累计）

1. **参数重复声明是致命的**：declare_parameter 同名参数第二次调用直接抛异常
   杀死进程，不会报编译错误
2. **PX4 话题必须 best_effort 订阅**：reliable 订阅收到零消息，唯一线索是
   节点日志里一条 "incompatible QoS" WARN
3. **WSL 文件系统（/mnt/g）的 mtime 不可靠**：代码改了但 colcon 不重编，
   必须 rm -rf build/ 后全量重编
4. **每换一个节点模板，要检查它做的所有"隐性服务"**：simple_below_tracker
   的隐性服务完整清单（两次踩坑后补全）：跟踪控制、auto-engage、task origin、
   setpoint 心跳、**common_origin（NavSatFix）**、**takeoff_ready（Bool）**、
   **setpoint 未用字段置 NaN**
5. **Python 数值验证先行的价值**：92% 触发 + 100% 命中证明算法正确，
   Gazebo 里的所有问题都是集成层面的（QoS/参数/帧ID/时序），不需要怀疑算法
6. **TrajectorySetpoint 是"全字段"消息**：没用的一定要 NaN，零值是合法设定点
7. **多工作区遮蔽要用 `ros2 pkg prefix` 验证**：以为在跑的包不一定是
   正在跑的包（裁判旧版静默跑了整整一天）
8. **诊断埋点一次加够**：计数器 + 分解输出（不是单个 bool），一次运行
   就能把"哪一层断了"钉死，比反复抓包快得多
