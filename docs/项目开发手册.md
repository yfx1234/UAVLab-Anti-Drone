## 2. 硬性红线（任何改动不得违反）

1. 软件永不自动解锁/起飞/切模式/自动降落；
2. 进 `/fmu/in` 的只有 OffboardControlMode / TrajectorySetpoint /
   VehicleAttitudeSetpoint 三类；**VehicleCommand 永久拦截**；
3. `px4_upstream_adapter` 默认 shadow；Live 需三参数显式确认；
4. `px4_upstream_adapter_node` 内 2026-08-13 预热补丁不得当普通代码清理；
5. 网枪触发**不走 MAVLink**，独立信号通道（现为 VirtualShotEvent 事件）；
6. 真值隔离：控制/火控侧不订阅任何真值话题，真值只进裁判与评分；
7. 主台账"外场特调参数 12 项"未逐项核对前不得归一化。

## 3. 网枪链已定决策总表（v1→v4 + §12，按主题）

### 3.1 传感与几何
- 单副双目，**4mm 焦距**，机头竖直向上安装，**视场长边沿机头**（待实测标定回填内参）；
- 深度仅 ≤10m 有效（逐消息 `depth_valid` 截断；仿真参数
  `depth_camera_maximum_depth_m`，默认 1e9 不影响旧行为）；
- **光轴 = body −Z = 攻击轴 = 网射向**，四者同轴（核心几何约定）；
- 观测分层：>10m `SearchObservation`（双目平均方位），≤10m `DepthObservation`；
- 仿真深度相机本就竖直向上（`default_upward_optical_quaternion`），挂载免改。

### 3.2 交战几何
- 全程 ≤12m；**向正下方逼近，下方保持约 6.2m**（不要求严格正下方，
  大倾斜几何允许——火控门为纯角度制，与倾斜无关）；
- 仿真初始布置：目标 (0,0)、追踪机 **(0,-12)**（`PURSUER_POSE="0,-12,0.01"`）；
- 双机模型沿用 px4sim 现状：目标 gz_x500（autostart 4001）、
  追踪机 gz_my_quad_real（autostart 22001），不动。

### 3.3 火控律（最终版）
```
开火 = 授权门(armed∧offboard∧高度≥1.5m∧attack_enable_delay_s)
     ∧ 估计门(有效∧新鲜≤0.45s∧measurement_accepted)
     ∧ 距离门 range∈[6,10]
     ∧ LOS角速率门 ≤0.5 rad/s
     ∧ 择时：主支 轴误差≤1° 即打；兜底 1°–2° 持续0.2s（抖动下难触发）
     ∧ 单发闩锁（触发后永久闭锁，无再攻路径）
无 0.04s 去抖（原 25fps 两帧保证已废）。
放宽测试档：2° 即打 / 4° 硬门（config/netgun_strike_relaxed.yaml），
S4 与标准档 A/B。
```
- 蒙射支：接口完整、**默认关闭**（8° 门/穿出前瞻 0.25s/超时支，
  全部有测试覆盖）；
- 预测方向 = IMM 预测(tof+展开 0.30s)目标位置方向 − 本机速度×lead
  （**本机速度补偿已实现**，默认开，消除 55m/s 下 2m/s 漂移≈2° 的系统偏差）。

### 3.4 网枪模型（V5-C 档，单一真源）
`muzzle_speed=55 m/s`、覆盖 3×3 正方形半幅 1.5m、展开 0.15s、
有效 [6,10]、单发；接口 `time_of_flight(range)=range/55` 与
`covered(x,y,range)`。V5 全模型（RK4/时间基展开/Rician）留接口可替换。

### 3.5 裁判
- 系统**保留**；C++ `virtual_interception_referee` 加 `instant_coverage_mode`
  （**默认 false 旧行为不变**，网枪链开启）：触发时刻目标相对射击轴横向
  分解（正交基投影），|x|,|y|≤1.5m ∧ 距离∈[6,10] 即命中，无弹丸外推；
- **相对系→绝对系转换在裁判桥完成**（strike 事件的估计量为
  frame_id=pursuer_local_ned 相对系）；
- Python `virtual_referee.py` 保留不动（旧链仿真辅助）。

### 3.6 估计器
- IMM **CV/CA/CT 三模**（已实现）：内部 10 维(+转弯率 ω)、3×3 转移
  （cv_to_cv 0.97 / ca_to_ca 0.95 / ct_to_ct 0.95，非对角均分）、
  初始 [0.6, 0.25, 0.15]；CT 水平一阶展开（50Hz 误差<10⁻³，精确圆弧留接口）；
- 消息 `model_probabilities` [2]→[3]，旧消费方按 [1] 取 CA 语义不变。

### 3.7 架构
- 新包 `netgun_intercept`（ament_cmake）：netgun_model / netgun_fire_control
  纯逻辑库 + netgun_strike_node + config×2 + launch；
- 上游仅四处就地小改，全部默认值保旧行为：`enable_native_fire`（默认
  true）、裁判 instant 模式（默认 false）、仿真 max depth（默认无限制）、
  IMM 三模（估计质量升级，行为兼容）。

### 3.8 偏航律（两段）
转段 **yaw=航向**（atan2 地速，低速保持）；末端保持段 **yaw=目标视线
方位**（长边沿机头 → 目标落在 FOV 长边、前后余度最大）。实现位置：
S1 核对 simple_below_tracker 的 yaw 策略。

## 4. 物理依据（为什么这些门限是合理的）

- **换算基准**：1° ↔ 0.14m@8m；3×3 半幅 1.5m ↔ 10.6°@8m、13.6°@6.2m。
- **抖动穿越论证**：多旋翼位置保持→姿态持续被激励→光轴 1–3Hz 绕目标
  抖动、周期性穿越零点；悬停散射 ±0.3–0.8m ↔ 轴误差 ±2–6°。因此
  **保持型门几乎不可触发（0.2s 兜底承认此点），而"≤1° 即打"吃的就是
  穿越瞬间**——50Hz 火控必捕获最优时刻，无需稳态对准。裕度约 10 倍
  （门 1° vs 覆盖 10.6°），瓶颈不在门限。
- **误差预算@8m（RSS≈0.4–0.7m vs 1.5m 半幅）**：门内轴误差 ≤0.14m；
  IMM 0.30s 预测误差 0.2–0.5m（CT 模型压机动场景）；网展开散布
  （实测前未知 0.3–0.5m 量级）；本机漂移已补偿。
- **延迟分析（§12.3，未实现）**：相机 0.2s 由"时间戳=曝光时刻+按戳
  消费"自动吸收（残余 ±0.1m）；触发 0.5s 使 horizon 0.30→0.80s——
  需 (a) `trigger_delay_s` 扩 lead（本机速度补偿同步扩），
  (b) 开火门改为"网到达时刻预测误差进窗"，(c) 0.8s 下机动目标
  0.5at²≈0.64m 正是 CT 的价值所在。两段延迟都要实测标定。

## 12. Python 一比一镜像与数值验收（2026-10-11）

工具：`netgun_intercept/scripts/netgun_mirror.py`（节点镜像库）+
`netgun_mirror_run.py`（场景矩阵/参数扫描运行器）。复刻对象：
仿真相机（上向安装/内参/像素与深度噪声/10m 截断/FOV 门）→
RelativeEstimator（光学→body→NED 官方映射、测量协方差、IMM 三模、
**max_data_age_s=0.5 有效性门**）→ simple_below_tracker（增益律/预测/
速度限幅/观测过期停车）→ 终端对准（2s 保持+1s 渐入指向预测视线，30°
限幅——生产链 terminal_alignment 语义）→ 机体（速度环+姿态滞后+OU 湍流）
→ 火控（逐分支同构）→ 裁判（3×3 即时，双延迟评估）。

**基线结果（1°/2° 档，静止→5m/s × 直线/加速/圆周，168 轮）**：
触发率 93%（分格 67–100%）；**命中@0s 触发延迟 = 99%**（横偏均值
0.16–0.70m vs 1.5m 半幅）；触发时轴误差 0.70–0.82°；开火多发生在交战
开始后 0.1–4.5s。**命中@0.5s 延迟 = 56%**（≥2m/s 恶化至 0–75%）——
§12.3 的延迟补偿（trigger_delay_s + 到达时刻预测门）优先级被定量证实。

复刻过程中修正的三个模型要点（真实链同样适用）：
1. 估计有效性门（断观测 0.5s 禁开火）是防"打幽灵"的关键——缺它时
   长断观测期估计漂移可达 20m 且火控会自信地朝幽灵开火；
2. 场景必须含建立期（对应 Gazebo target_motion_delay_s）：冷启动追击
   时 2m/s 目标 3s 即出深度泡，结构性不可拦；
3. 纯速度环 tracker 无法指轴（正下方滞后 v/gain 折算 15–39° 偏角），
   1° 火控窗必须依赖终端对准段——网枪链在 Gazebo 里也要保证这一环
   （simple_below_tracker 不提供，需 attitude 对准行为或换
   pure_interceptor 链）。

参数扫描入口：`py netgun_mirror_run.py --sweep thresholds|los|noise`
（放宽档 2°/4°、LOS 门、IMM 过程噪声已预置；kwargs 可任意组合）。
结论按同名参数 1:1 迁移 Gazebo/板端。
