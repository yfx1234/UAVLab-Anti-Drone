# 安装参数与标定（2026-10-22，10-23 修订）

## 结论

- 面板「拦截任务 → 安装参数」（默认收起）以**网枪顶面中心**（枪口中心）为基准填写相机顶面、RTK 天线、飞控位置和右目朝向。参数保存在板上 `~/netgun_config/mounting_geometry.json`（运行配置，不入 Git；旧文件留档 `history/`，保留 20 份），**下次启动拦截链生效**（运行中的拦截链不热更新，重启拦截链后生效）。文件无效时拦截链拒绝启动，不静默退回默认值。
- 10-23 修订（用户口径）：网枪顶面与相机顶面平行且同高；RTK 天线在相机正下方、距相机底面 8.5 cm；飞控在网枪正下方约 18 cm；枪轴 = 拦截器轴线，相机光轴与之平行、无夹角——**不再做枪轴核对**，枪轴偏角字段与读数已移除，火控 `boresight_*` 固定 0。面板不放说明文字。
- 默认值按用户口径，**未实测**：

| 项目 | 前 | 右 | 下 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 相机顶面 | 0 cm | 6 cm | 0 cm | 镜头面中心（两镜头中点）；与网枪顶面同高 |
| RTK 天线 | 0 cm | 6 cm | 12.2 cm | 相机厚 3.7 cm + 相机底面到天线中心 8.5 cm |
| 飞控 | 0 cm | 0 cm | 18 cm | 按“距网枪顶面 18 cm”理解；若从网枪底部量，需加网枪长度 |
| 右目朝向 | 朝机头 | | | 相机朝天，基线沿机头方向 |

- 飞控 RTK 天线偏置只给建议值 `EKF2_GPS_POS_X/Y/Z`（默认 0 / 0.060 / −0.058 m，天线在飞控上方 5.8 cm），由飞手在 QGC 设置。面板和板上脚本**从不写飞控参数**。

## 坐标与换算

机体 FRD（前、右、下为正，米），录入原点 = 网枪顶面中心；相机朝天（光轴 = 机体 −Z）。拦截链内部原点仍是飞控（与 PX4 姿态、本地位置同一参考点），换算由 `deploy/mounting_geometry.py` 完成：

- 左目光心（ZED 坐标原点）= 相机顶面 + 2 cm（光心在镜头面以下，机体 +Z）− 25 mm × 右目方向（ZED X Mini 基线 50 mm）。2 cm 与 3.7 cm 取自 Stereolabs `zed-ros2-description` 的 zedxm 模型：前表面在相机中心前 15.5 mm、光心在中心后 5 mm，机身厚 36.7 mm（不含背面 GMSL2 接口约 11 mm）。
- 估计器 `camera_translation_body = 左目光心 − 飞控`；`camera_q_body_to_optical`（w, x, y, z）按右目朝向：朝机头 (0, 1, 0, 0)、朝机尾 (0, 0, 1, 0)、朝右 (0, √½, √½, 0)、朝左 (0, √½, −√½, 0)。
- 火控 `muzzle_offset_body = 网枪顶面中心 − 飞控`；`boresight_pitch/yaw` 保持 launch 默认 0（只留作工程覆盖）。
- 飞控 `EKF2_GPS_POS = RTK 天线 − 飞控`（按飞控 ≈ 重心近似；PX4 该参数以重心为原点。若飞控不在重心，另需 `EKF2_IMU_POS_X/Y/Z`，RTK 偏置改为相对重心）。

默认值换算结果：`camera_translation_body = (−0.025, 0.060, −0.160) m`，`muzzle_offset_body = (0, 0, −0.180) m`，`boresight = 0`。火控瞄准用“目标 − 枪口”，飞控位置在其中相消，只剩相机光心相对枪口的 (−2.5, 6, 2) cm；飞控位置影响的是目标在 NED 中的位置（约 18 cm 级）与 RTK 偏置。

范围：位置 ±50 cm，最多两位小数。旧版（v1，以网枪中心为基准、含枪轴偏角）文件不再接受，需在面板重新保存。

## 生效与留痕

- `deploy/run_interceptor_stack.sh start` 先运行 `mounting_geometry.py launch-args`，把换算结果作为 `netgun_real.launch.py` 参数传入（命令行显式参数排在后面，仍可覆盖）；实际使用的参数以 `NETGUN_GEOMETRY {...}` 行写在运行日志开头，启动输出多一行参数摘要。
- `deploy/interceptor_status.py` 输出 `geometry.saved`（板上已保存）与 `geometry.applied`（最新日志启动时实际使用）。面板状态：默认值（未保存）、已保存、运行中 · 已生效、重启后生效、运行中参数未知（旧版本或手动启动）、参数文件无效、未保存修改；细节在状态的悬停提示里。
- SSH 查看：`python3 ~/interceptor_ws/deploy/mounting_geometry.py show | launch-args | brief`；核对运行中节点：`ros2 param get /pursuer/relative_estimator camera_translation_body_z_m`、`ros2 param get /pursuer/netgun_strike_node muzzle_offset_body_z_m`。

## 飞控需要标定吗

需要做 PX4 常规传感器校准，由飞手在 QGC 完成（面板不做）：

1. 加速度计、陀螺仪、磁罗盘、水平校准（Level Horizon）。装上网枪、相机、电池和 RTK 之后，在最终构型下重做罗盘校准；RTK 模块若带罗盘，一并校准并确认优先级。
2. 核对 `SENS_BOARD_ROT` 与飞控实际安装方向一致。

影响：拦截链用飞控姿态把相机测量转到 NED，航向误差会让相对几何整体旋转，影响跟踪、制导与任务原点锁存。开火门比较的是机体系内枪轴与目标视线的夹角，姿态误差大部分相消；决定命中的是相机与枪轴的相对夹角（用户确认平行）和相机相对枪口的平移（已由安装参数补偿）。

## RTK 需要标定吗

RTK 本身无需像 IMU 那样标定，但需要：

1. 在飞控填天线杠杆臂 `EKF2_GPS_POS_X/Y/Z`（面板「飞控 RTK 天线偏置」给出建议值，默认 0 / 0.060 / −0.058 m）。
2. 起飞前确认基站正常、定位为 RTK 固定解。

对拦截链影响较小：拦截链用视觉相对位置，RTK 主要影响 PX4 本地位置/速度质量（Offboard 位置控制与任务原点）。
