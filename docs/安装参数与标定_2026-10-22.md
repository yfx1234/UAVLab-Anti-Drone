# 安装参数与标定（2026-10-22）

## 结论

- 面板「拦截任务 → 安装参数」（默认收起）以**网枪中心**为基准填写相机中心、RTK 天线、飞控位置、右目朝向和枪轴偏角。参数保存在板上 `~/netgun_config/mounting_geometry.json`（运行配置，不入 Git；旧文件留档 `history/`，保留 20 份），**下次启动拦截链生效**；运行中的拦截链不受影响。文件无效时拦截链拒绝启动，不静默退回默认值。
- 默认值按 2026-10-22 用户口径，**未实测**：

| 项目 | 前 | 右 | 下 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 相机中心 | 0 cm | 6 cm | 0 cm | 轴线右侧 6 cm；与网枪中心的高度差待量 |
| RTK 天线 | 0 cm | 6 cm | 8.5 cm | 按“相机正下方 8.5 cm”（机体竖直向下）理解 |
| 飞控 | 0 cm | 0 cm | 0 cm | 未给；暂按在中轴线上、与网枪中心重合 |
| 右目朝向 | 朝机头 | | | 相机朝天，基线沿机头方向 |
| 枪轴偏角 | 前偏 0° | 右偏 0° | | 待枪轴核对 |

- 飞控 RTK 天线偏置只给建议值 `EKF2_GPS_POS_X/Y/Z`（默认 0 / 0.060 / 0.085 m），由飞手在 QGC 设置。面板和板上脚本**从不写飞控参数**。

## 坐标与换算

机体 FRD（前、右、下为正，米），录入原点 = 网枪中心；相机朝天（光轴 = 机体 −Z）。拦截链内部原点仍是飞控（与 PX4 姿态、本地位置同一参考点），换算由 `deploy/mounting_geometry.py` 完成，面板用同一公式实时显示（`tests/test_mounting_geometry.py` 校验两者一致）：

- 左目（ZED 坐标原点）= 相机中心 − 25 mm × 右目方向（ZED X Mini 基线 50 mm）。
- 估计器 `camera_translation_body = 左目 − 飞控`；`camera_q_body_to_optical`（w, x, y, z）按右目朝向：朝机头 (0, 1, 0, 0)、朝机尾 (0, 0, 1, 0)、朝右 (0, √½, √½, 0)、朝左 (0, √½, −√½, 0)。
- 火控 `muzzle_offset_body = 网枪中心 − 飞控`；枪轴 = normalize(tan 前偏, tan 右偏, −1)，即 `boresight_pitch = −atan(hypot(tan 前偏, tan 右偏))`、`boresight_yaw = atan2(tan 右偏, tan 前偏)`，偏角为 0 时与旧口径（枪管同轴光轴）逐位一致。
- 飞控 `EKF2_GPS_POS = RTK 天线 − 飞控`（按飞控 ≈ 重心近似；PX4 该参数以重心为原点。若飞控不在重心，另需 `EKF2_IMU_POS_X/Y/Z`，RTK 偏置改为相对重心）。

默认值换算结果：`camera_translation_body = (−0.025, 0.060, 0.000) m`（原 launch 默认 y = 0.05 已按 6 cm 更新），`muzzle_offset_body = 0`，`boresight = 0`。

范围：位置 ±50 cm、偏角 ±10°，最多两位小数。

## 生效与留痕

- `deploy/run_interceptor_stack.sh start` 先运行 `mounting_geometry.py launch-args`，把换算结果作为 `netgun_real.launch.py` 参数传入（命令行显式参数排在后面，仍可覆盖）；实际使用的参数以 `NETGUN_GEOMETRY {...}` 行写在运行日志开头，启动输出多一行参数摘要。
- `deploy/interceptor_status.py` 输出 `geometry.saved`（板上已保存）与 `geometry.applied`（最新日志启动时实际使用）。面板状态：默认值（未保存）、已保存、运行中 · 已生效、重启后生效、运行中参数未知（旧版本或手动启动）、参数文件无效、未保存修改。
- SSH 查看：`python3 ~/interceptor_ws/deploy/mounting_geometry.py show | launch-args | brief`。

## 飞控需要标定吗

需要做 PX4 常规传感器校准，由飞手在 QGC 完成（面板不做）：

1. 加速度计、陀螺仪、磁罗盘、水平校准（Level Horizon）。装上网枪、相机、电池和 RTK 之后，在最终构型下重做罗盘校准；RTK 模块若带罗盘，一并校准并确认优先级。
2. 核对 `SENS_BOARD_ROT` 与飞控实际安装方向一致。

影响：拦截链用飞控姿态把相机测量转到 NED，航向误差会让相对几何整体旋转，影响跟踪、制导与任务原点锁存。开火门比较的是机体系内枪轴与目标视线的夹角，姿态误差大部分相消；真正决定命中的是**相机与枪轴的相对夹角**（1° 安装误差 ≈ 1° 瞄准误差，主开火门 2°、窗口 4°）和相机 6 cm 平移（4–9.8 m 处约 0.86°–0.35° 视差，已由安装参数补偿）。

## RTK 需要标定吗

RTK 本身无需像 IMU 那样标定，但需要：

1. 在飞控填天线杠杆臂 `EKF2_GPS_POS_X/Y/Z`（面板「飞控 RTK 天线偏置」给出建议值，按上文默认 0 / 0.060 / 0.085 m）。
2. 起飞前确认基站正常、定位为 RTK 固定解。

对拦截链影响较小：拦截链用视觉相对位置，RTK 主要影响 PX4 本地位置/速度质量（Offboard 位置控制与任务原点）。

## 枪轴核对（相机 ↔ 枪管夹角）

不需要启动拦截链，只需相机 + YOLO 运行：

1. 拦截器放稳、相机朝天；在**枪管延长线**上方 4–10 m 放目标（枪管内激光校靶、吊线或天花板投点），确保目标为“有效深度”（尺寸估计、仅方向不参与读数）。
2. 展开「安装参数 → 枪轴核对」，先核对朝向：目标移向机头时“前”应增大、移向右侧时“右”应增大，否则改右目朝向。**右目朝向错了会让前后或左右反向，跟踪发散**，修改后必须先核对。
3. 目标在枪轴上且读数稳定后，按「按读数填入枪轴偏角」→「保存参数」→ 重启拦截链；“离轴”应接近 0。读数用的是面板当前填写值（含未保存修改）。
4. 在两个距离（如 4 m 和 8 m）复核：偏角随距离明显变化说明位置参数（相机中心，尤其高度）有误，而不是角度问题。
