# 双逻辑相机模型

本文只定义相机几何和输出权限。完整跟踪、状态机、质量门和两次虚拟打击
方案见 `docs/开发状态/双相机跟踪打击统一方案.md`。

本分支仅修改算法中的虚拟相机投影、坐标转换和视场判断，不修改
Gazebo/SDF、传感器实体、ROS 话题和 TF。

## 坐标约定

PX4 机体使用 FRD：`+X` 向前、`+Y` 向右、`+Z` 向下。标准光学坐标：
`+X` 图像向右、`+Y` 图像向下、`+Z` 沿视线。

攻击轴始终为：

```text
attack_axis_body = [0, 0, -1]
```

## 模拟双目深度相机

现有 `/tracking/camera/observation` 仅承载该相机观测，并继续使用原有真值
深度计算，不模拟基线、视差或三角测量。

```text
x_depth =  y_body
y_depth =  x_body
z_depth = -z_body
```

物理单相机垂直半视场为 13°，算法只采用双目重叠区域的保守半角 10°。
因此有效视场为水平 17°、垂直 20°；视场判断使用水平半角 8.5°和垂直
半角 10°。`depth` 是光轴深度 `z_depth`，内部 `range_m` 是三维欧氏
距离，两者含义不同。

3840×2160 逻辑图像使用与有效视场一致的独立针孔内参：

```text
depth_fx = 12847.019977569425
depth_fy =  6124.984365187126
depth_cx = 1919.5
depth_cy = 1079.5
```

## 搜索相机

搜索相机从机体 `-Z` 向 `+X` 偏转 10°：

```text
x_search = y_body
y_search = 0.984807753 * x_body + 0.173648178 * z_body
z_search = 0.173648178 * x_body - 0.984807753 * z_body
```

全视场为水平 35°、垂直 60°，对应机体纵向覆盖约为机尾方向 −20°至
机头方向 +40°，横向覆盖为 ±17.5°。

搜索相机公开的内部结果类型 `BearingObservation` 只有：

- 可见性；
- 像素坐标；
- 水平、垂直视线角；
- 光学坐标系单位视线。

该类型没有深度、距离或三维目标位置字段。由于现有 ROS 消息结构保持不变，
搜索相机结果当前不另行发布，只在观测节点内部计算并记录目标获得/丢失状态。

搜索相机的 10°安装倾角不得加入最终攻击瞄准条件；最终攻击仍使用机体
`-Z`/深度相机中心轴。

搜索相机不再复用双目相机焦距。3840×2160 逻辑图像使用：

```text
search_fx = 6089.462020537369
search_fy = 1870.614872174388
search_cx = 1919.5
search_cy = 1079.5
```

这样两个逻辑相机的视场边界分别映射到各自图像边界。投影得到的
`pixel_u/pixel_v` 可作为理想 YOLO 检测框中心；搜索相机仍不输出检测框
尺度、距离或三维位置。
